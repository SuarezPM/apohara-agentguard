## 1. Sentinel PRs — Security Fix (5 duplicates → merge #53)

### Recommended: #53
- **Approach:** SHA-256 hash of `session_id` → fixed-length hex filename
- **Why best:** Most robust (hash eliminates all path traversal vectors), smallest diff (+68/-1), newest, CI green
- **Action:** Merge #53, close #35, #47, #50, #51 as duplicates

### Duplicate PRs to close:

| PR | Approach | Why inferior to #53 |
|----|----------|---------------------|
| #35 | Strict character allowlist | Earlier iteration, larger diff, less robust |
| #47 | `is_safe_session_id` + tests | Larger diff (+128/-4), allowlist approach |
| #50 | `is_safe_session_id` + None/InvalidInput | Allowlist approach, 1-file only |
| #51 | Strict character allowlist | Allowlist approach, slightly smaller than #47 |

### Rationale:
All 5 PRs fix the same vulnerability (canary token path traversal). The allowlist approach (#35,#47,#50,#51) is sound but requires maintaining a character class. The SHA-256 approach (#53) is self-contained — any valid string becomes a safe filename. Smaller diff = less review surface.
